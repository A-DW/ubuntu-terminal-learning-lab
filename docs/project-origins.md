# Project origins

## Why I started

I started this project while preparing for Canonical Academy's Ubuntu Using Linux Terminal certification. I wrote study notes covering file navigation and processing, shell redirection, system resources and filesystem access security. I wanted to move beyond recognising commands to using them in practical tasks.

I designed a six-block practice programme with AI assistance. I wanted realistic administration scenarios, reproducible synthetic fixtures, optional hints, separate solutions and one review of a complete task batch rather than an oral quiz after every command.

## From domains to blocks

My starting material has three domain groupings and one shell-operators companion. I reorganised the practice into six blocks:

1. Files and navigation.
2. Text and pipelines.
3. Logs and scheduling.
4. Storage.
5. Accounts and access.
6. SSH and sudo.

This organisation reflects how I want to learn. I do not present it as an official exam blueprint or weighting.

## My first practical checkpoint

I completed a Project Atlas file-management exercise on CLIENT and submitted an initial attempt followed by remediation. The review highlighted file-type inspection, metadata, attribute-preserving copying, relative symbolic links and the need to capture the exit status of the actual check.

I closed Block 1 as guided learning after understanding the remaining issues. I did not resubmit every final functional check, so I do not describe it as a fully verified first-attempt pass. My [checkpoint summary](../blocks/block-01-files-and-navigation/README.md) keeps those limits explicit.

## Why I preserve mistakes

I want a useful learning record, not a reconstructed perfect performance. I preserve unsuccessful commands and relevant errors when I publish an attempt, place corrected examples in solutions, and label any redactions.

Repository commits record publication changes. I do not backdate imports or imply that a later documentation commit proves when a command originally ran.
